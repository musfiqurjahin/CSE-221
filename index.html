Topic 01

Minimum Spanning Tree (MST)

A Minimum Spanning Tree connects all vertices of a weighted, undirected, connected graph with the minimum possible total edge weight, using no cycles. Below the topic is built up from raw graph definitions to full correctness proofs and algorithm variants.

Graph FundamentalsBasic

Before MST makes sense, these terms must be second nature:

  • Graph G = (V, E): a set of vertices V and edges E connecting pairs of vertices.
  • Weighted graph: every edge has a numeric cost/weight (distance, cost, time, etc.).
  • Undirected graph: edge (u, v) is the same as (v, u) — no direction.
  • Connected graph: there exists a path between every pair of vertices.
  • Path: a sequence of edges connecting a sequence of distinct vertices.
  • Cycle: a path that starts and ends at the same vertex with no repeated edges.
  • Tree: a connected graph with no cycles. A tree on n vertices always has exactly n − 1 edges.
  • Forest: a disjoint union of trees (i.e., an acyclic graph that may be disconnected).
  • Cut: a partition of V into two disjoint non-empty subsets (S, V − S). An edge "crosses" the cut if it has one endpoint in each subset.

What Makes a Spanning Tree "Minimum"?Basic

Definition

A Spanning Tree of a connected graph G is a subgraph that (a) includes every vertex of G, (b) is connected, and (c) is acyclic — hence it uses exactly |V| − 1 edges.

A Minimum Spanning Tree (MST) is a spanning tree whose sum of edge weights is the smallest possible among all spanning trees of G.

  • A connected graph can have many different spanning trees. (By Cayley's formula, a complete graph on n labeled vertices has exactly nn−2 spanning trees.)
  • MST is defined only for connected graphs — a disconnected graph instead yields a Minimum Spanning Forest (one MST per connected component).
  • Uniqueness: if all edge weights in the graph are distinct, the MST is guaranteed to be unique. If weights repeat, multiple different MSTs may exist — but they will all share the exact same total weight.

Greedy Strategy & Core PropertiesCore

Every MST algorithm is greedy: it repeatedly makes the cheapest safe choice available, without ever reconsidering it. This greedy strategy is provably correct because of two structural properties of MSTs:

1. Cut Property

For any cut (S, V − S) of the graph, if an edge e is the unique minimum-weight edge crossing that cut, then e belongs to every MST of the graph. (If there are ties for minimum, at least one of the tied edges belongs to some MST.)

Why it matters: both Prim's and Kruskal's are, at their core, repeated applications of the cut property — they always pick the cheapest edge crossing some meaningful cut.

2. Cycle Property

For any cycle in the graph, if an edge e is the unique maximum-weight edge in that cycle, then e cannot belong to any MST — removing it and keeping the rest is always at least as good.

This is the theoretical justification for why Kruskal's skips an edge that would close a cycle: that edge is never better than the alternative path already connecting its endpoints.

Prim's AlgorithmCore

Prim's grows the MST one vertex at a time. Starting from an arbitrary source vertex, it repeatedly adds the cheapest edge that connects a vertex already in the tree to a vertex not yet in the tree — a vertex-based greedy approach that directly applies the cut property, using the cut (tree-so-far, remaining vertices) at every step.

Idea / Steps

  1. Pick any starting vertex and mark it as "in MST".
  2. Maintain a key[] array — the minimum edge weight connecting each vertex to the growing tree (initialized to ∞, source = 0).
  3. Repeatedly pick the vertex not yet in MST with the smallest key value.
  4. Add it to the MST, and update the key values of its neighbours if a cheaper connecting edge is found.
  5. Repeat until all V vertices are included.

Pseudocode — Array-Based (O(V²))

PRIM(Graph G, source s):
    for each vertex v in G.V:
        key[v] = INFINITY
        parent[v] = NIL
        inMST[v] = false
    key[s] = 0

    for i = 1 to |V|:
        u = vertex not in MST with minimum key[u]   // O(V) scan
        inMST[u] = true

        for each neighbour v of u:
            if inMST[v] == false and weight(u, v) < key[v]:
                key[v] = weight(u, v)
                parent[v] = u

    return parent[]   // edges (parent[v], v) form the MST

Pseudocode — Min-Heap Based (O(E log V))

PRIM-HEAP(Graph G, source s):
    for each vertex v in G.V:
        key[v] = INFINITY
        parent[v] = NIL
    key[s] = 0
    Q = min-priority-queue keyed by key[], containing all vertices

    while Q is not empty:
        u = EXTRACT-MIN(Q)             // O(log V)
        for each neighbour v of u still in Q:
            if weight(u, v) < key[v]:
                key[v] = weight(u, v)
                parent[v] = u
                DECREASE-KEY(Q, v, key[v])   // O(log V)

    return parent[]
Adjacency Matrix: O(V²) Binary Heap + Adj List: O(E log V) Fibonacci Heap: O(E + V log V) Space: O(V + E)

Kruskal's AlgorithmCore

Kruskal's grows the MST by considering edges in increasing order of weight, and greedily adding an edge if it does not create a cycle — an edge-based greedy approach that applies the cycle property directly. Cycle detection is efficiently handled using the Disjoint Set Union (Union-Find) data structure.

Idea / Steps

  1. Sort all edges in non-decreasing order of weight.
  2. Initialize a disjoint-set (each vertex is its own parent/set).
  3. For each edge (u, v) in sorted order: if u and v belong to different sets, include the edge in MST and union the two sets.
  4. If they belong to the same set, including the edge would form a cycle — skip it.
  5. Stop once V − 1 edges are added.

Pseudocode

KRUSKAL(Graph G):
    A = ∅                          // set to hold MST edges
    for each vertex v in G.V:
        MAKE-SET(v)

    sort G.E by non-decreasing weight

    for each edge (u, v) in sorted G.E:
        if FIND-SET(u) ≠ FIND-SET(v):
            A = A ∪ {(u, v)}
            UNION(u, v)

    return A

Disjoint Set Union — Path Compression + Union by Rank

A naive Union-Find can degrade to O(n) per operation. Two optimizations bring it down to nearly O(1) amortized:

  • Union by Rank/Size: always attach the smaller/shallower tree under the root of the larger/deeper one, keeping trees flat.
  • Path Compression: during FIND, make every visited node point directly to the root, flattening the structure for future queries.
MAKE-SET(x):
    parent[x] = x
    rank[x] = 0

FIND-SET(x):
    if parent[x] ≠ x:
        parent[x] = FIND-SET(parent[x])   // path compression
    return parent[x]

UNION(x, y):
    rx = FIND-SET(x)
    ry = FIND-SET(y)
    if rx == ry: return          // already connected -> would form a cycle
    if rank[rx] < rank[ry]:
        swap(rx, ry)
    parent[ry] = rx
    if rank[rx] == rank[ry]:
        rank[rx] = rank[rx] + 1

With both optimizations, a sequence of m operations on n elements runs in O(m · α(n)) time, where α is the inverse Ackermann function — grows so slowly it is effectively a constant (≤ 4) for any input size in the real world.

Sorting edges: O(E log E) Union-Find ops: O(E · α(V)) ≈ O(E) Total: O(E log E) = O(E log V) Space: O(V + E)

Correctness Proof (Sketch)Advanced

Proof by Induction (applies to both Prim's and Kruskal's)

Claim: at every step, the set of edges chosen so far is a subset of some MST.

Base case: with 0 edges chosen, the empty set is trivially a subset of any MST.

Inductive step: assume the edges chosen so far, A, are a subset of some MST T. The algorithm now adds an edge e that is the minimum-weight edge crossing some cut respecting A (Prim's: tree vs. rest; Kruskal's: the two components e would merge). By the cut property, e belongs to some MST. If e ∈ T already, A ∪ {e} stays a subset of T. If not, adding e to T creates a cycle; removing the (necessarily heavier, by minimality of e) other cut-crossing edge in that cycle produces a new MST T′ that contains A ∪ {e}. Either way, the invariant holds.

Conclusion: when the algorithm terminates with V − 1 edges, that edge set is itself a spanning tree contained in some MST — hence it is an MST.

Variants & ExtensionsAdvanced

Borůvka's Algorithm

The oldest MST algorithm (1926). It repeatedly, for every component, finds the cheapest edge leaving that component and adds all such edges simultaneously (merging components), then repeats. Since each round at least halves the number of components, it terminates in O(log V) rounds. 

BORUVKA(Graph G):
    A = ∅
    for each vertex v: MAKE-SET(v)
    numComponents = |V|

    while numComponents > 1:
        cheapest[] = NIL for every component
        for each edge (u, v, w) in G.E:
            cu = FIND-SET(u); cv = FIND-SET(v)
            if cu ≠ cv:
                if cheapest[cu] is NIL or w < cheapest[cu].w:
                    cheapest[cu] = (u, v, w)
                if cheapest[cv] is NIL or w < cheapest[cv].w:
                    cheapest[cv] = (u, v, w)

        for each component c with cheapest[c] ≠ NIL:
            (u, v, w) = cheapest[c]
            if FIND-SET(u) ≠ FIND-SET(v):
                UNION(u, v); A = A ∪ {(u, v)}
                numComponents = numComponents − 1

    return A
Time: O(E log V) Naturally parallelizable

Other Advanced Notes

  • Second-Best MST: for each non-tree edge, find the max edge on the tree path it would create a cycle with; the second-best MST swaps in the smallest such replacement (uses techniques like binary lifting for max-edge-on-path queries).
  • Minimum Spanning Forest: for a disconnected graph, both Prim's (run once per component) and Kruskal's (naturally, since it processes global edges) produce a forest of per-component MSTs.
  • Applications: network design (minimum cost cabling/piping), approximate algorithms for the Traveling Salesman Problem (2-approximation via MST), clustering (removing the k−1 most expensive MST edges gives k clusters), circuit design.

Topic 02

Huffman Coding

A greedy algorithm for lossless data compression that assigns variable-length binary codes to characters based on their frequency — shorter codes for frequent characters, longer codes for rare ones.

Data Compression FundamentalsBasic

  • Lossless compression: the original data can be perfectly reconstructed from the compressed form (Huffman coding is lossless). Contrast with lossy compression (e.g. JPEG), where some information is discarded permanently.
  • Fixed-length codes: every symbol uses the same number of bits (e.g. ASCII uses 8 bits/character regardless of frequency).
  • Variable-length codes: different symbols may use a different number of bits — this is where Huffman coding's savings come from.
  • Prefix code (a.k.a. prefix-free code): no codeword is a prefix of any other codeword. This property guarantees a bitstream can be decoded unambiguously, left to right, with no delimiters needed.
Why Not Just Use Fixed-Length Codes?

Fixed-length encoding wastes space when character frequencies are skewed. If 'e' appears far more often than 'z', giving 'e' a short (e.g. 2-bit) code and 'z' a longer (e.g. 7-bit) code reduces the average bits per character, and hence total file size — provided the codes remain prefix-free.

Theoretical Lower Bound — Entropy

Shannon's source coding theorem states that the theoretical minimum average number of bits per symbol is the entropy:

H(X) = − Σ p(x) · log₂ p(x), summed over all symbols x with probability p(x).

Huffman coding gets very close to this bound (within 1 bit per symbol in the worst case), and achieves it exactly when all probabilities are exact powers of ½.

Huffman's Greedy AlgorithmCore

Huffman coding builds a binary tree — the Huffman Tree — bottom-up, where more frequent characters end up closer to the root (shorter codes) and rarer characters end up deeper (longer codes). It minimizes the total encoded length Σ freq(c) × depth(c).

Algorithm / Steps (using a Min-Heap)

  1. Compute the frequency of every character in the input.
  2. Create a leaf node for each character and insert all into a min-priority-queue keyed by frequency.
  3. While more than one node remains in the queue: extract the two nodes of smallest frequency.
  4. Create a new internal node with these two as children, with frequency = sum of the two.
  5. Insert the new node back into the priority queue.
  6. Repeat until only one node remains — this is the root of the Huffman Tree.
  7. Assign 0 to every left edge and 1 to every right edge; the code for a character is the path from root to its leaf.

Pseudocode — Building the Tree

HUFFMAN(C):                          // C = set of characters with frequencies
    n = |C|
    Q = min-priority-queue initialized with C   // keyed by freq

    for i = 1 to n − 1:
        z = new Node()
        z.left  = x = EXTRACT-MIN(Q)
        z.right = y = EXTRACT-MIN(Q)
        z.freq  = x.freq + y.freq
        INSERT(Q, z)

    return EXTRACT-MIN(Q)          // root of the Huffman tree

Pseudocode — Generating Codes

GENERATE-CODES(node, prefix, codeTable):
    if node is a leaf:
        codeTable[node.char] = prefix   // (use "0" if the whole alphabet is one symbol)
        return
    GENERATE-CODES(node.left,  prefix + "0", codeTable)
    GENERATE-CODES(node.right, prefix + "1", codeTable)

Pseudocode — Decoding a Bitstream

DECODE(root, bitstream):
    output = ""
    node = root
    for each bit in bitstream:
        node = (bit == 0) ? node.left : node.right
        if node is a leaf:
            output = output + node.char
            node = root       // restart at root for next character
    return output

Proof of OptimalityAdvanced

Greedy-Choice Property

Claim: in an optimal prefix code, the two least-frequent characters have codewords of the same (maximum) length and differ only in the last bit — i.e. they are sibling leaves at the deepest level of some optimal tree.

Proof sketch (exchange argument): suppose an optimal tree T does not have the two least-frequent symbols x, y as deepest siblings. Take any two siblings a, b at the maximum depth of T (such siblings must exist since every internal node in an optimal tree has two children). Since x, y are the least frequent, freq(x) ≤ freq(a) and freq(y) ≤ freq(b). Swapping x ↔ a and y ↔ b cannot increase the total cost Σ freq(c)·depth(c) (moving a lighter symbol to a deeper position and a heavier one to a shallower position only helps or ties). Hence an optimal tree exists with x, y as deepest siblings.

Optimal substructure: once x and y are merged into a single node z with frequency freq(x) + freq(y), an optimal tree for the reduced alphabet (replacing x, y with z) combined with expanding z back into x, y gives an optimal tree for the original alphabet. This justifies the recursive greedy merging.

Variants & Practical ExtensionsAdvanced

  • Canonical Huffman Codes: re-assigns codewords using only the code lengths from the tree, in a standardized way — the tree itself doesn't need to be transmitted with the compressed data, only the lengths (used in DEFLATE/ZIP, JPEG).
  • Adaptive (Dynamic) Huffman Coding: builds/updates the tree on the fly as symbols are read, so it works in a single pass without needing frequencies upfront (e.g. the FGK and Vitter algorithms).
  • n-ary Huffman Coding: generalizes to an n-ary tree (n-way merges instead of 2-way) for alphabets larger than binary output.
  • Limitation vs. Arithmetic/Range Coding: Huffman coding must assign a whole number of bits per symbol, so it can lose efficiency when the ideal code length (from entropy) isn't an integer. Arithmetic coding can achieve closer-to-entropy compression by encoding entire messages as a single fractional number.
Common Pitfalls
  • Forgetting the edge case of a single distinct character (its code must still be non-empty, e.g. "0", even though prefix logic alone wouldn't require it).
  • Ties in frequency: any consistent tie-breaking rule still gives an optimal tree (same total bits), though the exact codewords may differ from another valid solution.
  • Huffman coding is optimal only among prefix codes — for non-prefix or block codes different bounds may apply.

  • Compute the Shannon entropy of a distribution and compare it to the Huffman-achieved average code length.
Topic 03

Dynamic Programming (DP)

A method for solving complex problems by breaking them into overlapping subproblems, solving each subproblem once, and storing (caching) results to avoid redundant work.

From Recursion to DPBasic

A naive recursive solution to Fibonacci repeats work: fib(5) calls fib(4) and fib(3), but fib(4) itself calls fib(3) again — the same subproblem is solved from scratch multiple times, and the recursion tree grows exponentially: 

                    fib(5)
                 /            \
            fib(4)             fib(3)
           /      \            /     \
        fib(3)   fib(2)     fib(2)   fib(1)
        /   \     /   \      /   \
    fib(2) fib(1) ...  ...  ...  ...
    // fib(3), fib(2) etc. are recomputed many times over

DP's core idea: compute each distinct subproblem only once, and reuse the stored answer — turning exponential time into polynomial time.

Optimal Substructure & Overlapping SubproblemsBasic

The Two Requirements for DP

Optimal Substructure: an optimal solution to the problem can be constructed from optimal solutions to its subproblems. (E.g., the shortest path from A to C through B is the shortest A→B path plus the shortest B→C path.)

Overlapping Subproblems: a recursive solution revisits the same subproblems repeatedly, rather than each subproblem appearing only once (which is more typical of Divide & Conquer, e.g. Merge Sort's subarrays never overlap).

Two DP ApproachesCore

ApproachDirectionMechanismTrade-offs
Memoization (Top-Down)Recursive, starts from the big problemRecursion + cache (array/map) to store computed resultsEasy to derive directly from the recurrence; some overhead from the recursion call stack
Tabulation (Bottom-Up)Iterative, starts from base casesFill a table iteratively in dependency orderUsually faster in practice, no recursion overhead, and allows further space optimization

General Design Steps

  1. Define the subproblem clearly — what does dp[i] or dp[i][j] represent?
  2. Write the recurrence relation connecting a state to smaller/previous states.
  3. Identify the base case(s).
  4. Decide computation order — top-down with memo, or bottom-up table fill.
  5. Optimize space, if possible — keep only the last row/column if the recurrence only needs the immediately preceding state.

Fibonacci — Both Approaches

// Top-Down (Memoization)
memo[] = {-1, -1, ..., -1}
FIB(n):
    if n ≤ 1: return n
    if memo[n] ≠ -1: return memo[n]
    memo[n] = FIB(n-1) + FIB(n-2)
    return memo[n]

// Bottom-Up (Tabulation), O(1) space
FIB-TAB(n):
    if n ≤ 1: return n
    prev2 = 0; prev1 = 1
    for i = 2 to n:
        cur = prev1 + prev2
        prev2 = prev1; prev1 = cur
    return prev1
Naive recursion: O(2ⁿ) DP: O(n) time Tabulation, space-optimized: O(1)

0/1 KnapsackCore

Given n items each with weight wt[i] and value val[i], and a knapsack of capacity W, maximize total value without exceeding capacity. Each item is taken whole or not at all — unlike the Fractional Knapsack (a greedy problem), items here cannot be split.

Recurrence Relation

Let dp[i][w] = max value achievable using the first i items with capacity w.

dp[i][w] = dp[i-1][w]  if wt[i] > w (item i doesn't fit)
dp[i][w] = max( dp[i-1][w], dp[i-1][w-wt[i]] + val[i] )  otherwise (skip item i, or take it)

Base case: dp[0][w] = 0 for all w (no items chosen → 0 value).

Pseudocode — 2D Table

KNAPSACK(wt[1..n], val[1..n], W):
    for w = 0 to W: dp[0][w] = 0

    for i = 1 to n:
        for w = 0 to W:
            if wt[i] > w:
                dp[i][w] = dp[i-1][w]
            else:
                dp[i][w] = max(dp[i-1][w], dp[i-1][w-wt[i]] + val[i])

    return dp[n][W]

Pseudocode — Space-Optimized 1D

Since row i only depends on row i-1, a single array suffices — as long as the inner loop runs in reverse, so each cell is updated using values not yet overwritten in the current pass.

KNAPSACK-1D(wt[1..n], val[1..n], W):
    dp[0..W] = 0

    for i = 1 to n:
        for w = W downto wt[i]:     // REVERSE order is essential
            dp[w] = max(dp[w], dp[w - wt[i]] + val[i])

    return dp[W]

Matrix Chain Multiplication (MCM)Core

Given a chain of matrices, find the optimal parenthesization (multiplication order) that minimizes total scalar multiplications. Matrix multiplication is associative, so order affects only cost, never the final result.

Dimensions given as p[0], p[1], ..., p[n], so matrix Aᵢ has dimension p[i-1] × p[i]. Let dp[i][j] = minimum cost to multiply Aᵢ...Aⱼ.

dp[i][i] = 0
dp[i][j] = min over k (i ≤ k < j) of { dp[i][k] + dp[k+1][j] + p[i-1]·p[k]·p[j] } 

MATRIX-CHAIN-ORDER(p[0..n]):
    for i = 1 to n: dp[i][i] = 0

    for len = 2 to n:                 // chain length
        for i = 1 to n - len + 1:
            j = i + len - 1
            dp[i][j] = INFINITY
            for k = i to j - 1:
                cost = dp[i][k] + dp[k+1][j] + p[i-1]*p[k]*p[j]
                if cost < dp[i][j]:
                    dp[i][j] = cost
                    split[i][j] = k          // remember the split point

    return dp[1][n]

The split[][] table lets you reconstruct the actual optimal parenthesization by recursively splitting at the recorded k.

Time: O(n³) Space: O(n²)

Longest Increasing Subsequence (LIS)Advanced

Given an array, find the length of the longest strictly increasing subsequence.

dp[i] = length of the LIS ending exactly at index i.

dp[i] = 1 + max( dp[j] ) for all j < i where arr[j] < arr[i]; if no such j exists, dp[i] = 1.

// O(n^2) DP
LIS(arr[1..n]):
    for i = 1 to n: dp[i] = 1
    for i = 2 to n:
        for j = 1 to i - 1:
            if arr[j] < arr[i] and dp[j] + 1 > dp[i]:
                dp[i] = dp[j] + 1
    return max(dp[1..n])

// O(n log n) using patience-sorting / binary search
LIS-FAST(arr[1..n]):
    tails = []                       // tails[k] = smallest possible tail of an increasing
                                      // subsequence of length k+1 found so far
    for each x in arr:
        pos = lower_bound(tails, x)  // first index with tails[pos] >= x
        if pos == length(tails):
            append x to tails
        else:
            tails[pos] = x
    return length(tails)
Basic DP: O(n²) time, O(n) space Patience sorting: O(n log n) time

Coin ChangeAdvanced

Variant A — Minimum coins to make an amount (unbounded supply of each denomination):

dp[0] = 0;   dp[a] = min over coin c ≤ a of { dp[a-c] + 1 }

Variant B — Count the number of ways to make an amount (order doesn't matter — process coins one denomination at a time to avoid counting permutations as distinct):

ways[0] = 1;   for each coin c, for a from c to amount: ways[a] += ways[a-c]

// Minimum coins
MIN-COINS(coins[1..m], amount):
    dp[0] = 0
    for a = 1 to amount: dp[a] = INFINITY
    for a = 1 to amount:
        for each c in coins:
            if c ≤ a and dp[a-c] + 1 < dp[a]:
                dp[a] = dp[a-c] + 1
    return dp[amount] or "impossible" if still INFINITY

// Count number of ways (order-independent)
COUNT-WAYS(coins[1..m], amount):
    ways[0] = 1
    for a = 1 to amount: ways[a] = 0
    for each c in coins:
        for a = c to amount:
            ways[a] = ways[a] + ways[a-c]
    return ways[amount]
Time: O(amount × coins) Space: O(amount)

DP Complexity Classes & Design NotesAdvanced

  • Pseudo-polynomial time: algorithms like Knapsack and Coin Change run in time polynomial in the numeric value of the input (e.g. W or amount), not in the number of bits needed to represent it — so they're technically exponential in input size for very large numeric values. This is why Knapsack is weakly NP-complete rather than solvable in strict polynomial time for arbitrary W.
  • Choosing the state: a good DP state captures exactly the information needed to make future decisions — no more, no less. Too little state breaks correctness; too much state blows up time/space unnecessarily.
  • Space-time tradeoffs: when only the previous row/column of a 2D table is needed, roll the table down to O(n) or O(1) space — a very common last-step optimization in exam answers.

Topic 04

Longest Common Subsequence (LCS)

A classic Dynamic Programming problem: given two sequences, find the length (and content) of the longest subsequence present in both — where a subsequence need not be contiguous, but must preserve relative order.

Subsequence vs SubstringBasic

  • Subsequence: derived by deleting zero or more characters without changing the relative order of the remaining characters. Characters need not be contiguous. E.g. "ACE" is a subsequence of "ABCDE".
  • Substring: a contiguous block of characters. E.g. "BCD" is a substring of "ABCDE", but "ACE" is not.
Definition — LCS

Given two strings X (length m) and Y (length n), the LCS is the longest sequence that is a subsequence of both.

Example: X = "ABCBDAB", Y = "BDCABA" → LCS = "BCBA" or "BDAB" (length 4).

Recurrence DerivationCore

Let dp[i][j] = length of LCS of X[1..i] and Y[1..j].

dp[i][0] = dp[0][j] = 0  (base case — an empty prefix has LCS length 0)

dp[i][j] = dp[i-1][j-1] + 1  if X[i] == Y[j]
dp[i][j] = max( dp[i-1][j], dp[i][j-1] )  if X[i] ≠ Y[j]

Why this holds: if the last characters of both prefixes match, they must both belong to the LCS (a proof by contradiction shows any LCS not using this matched pair can be extended by adding it, or rearranged to include it without loss). So the LCS extends the LCS of the two shorter prefixes by 1. If they don't match, at least one of X[i] or Y[j] cannot be part of a common LCS ending exactly there — so we take the better of excluding the last character of X or of Y.

Pseudocode — Length Only

LCS-LENGTH(X, Y):
    m = length(X); n = length(Y)
    for i = 0 to m: dp[i][0] = 0
    for j = 0 to n: dp[0][j] = 0

    for i = 1 to m:
        for j = 1 to n:
            if X[i] == Y[j]:
                dp[i][j] = dp[i-1][j-1] + 1
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])

    return dp[m][n]

Pseudocode — Reconstructing the Actual LCS String

Backtrack from dp[m][n]: if characters matched, that character is part of the LCS and both indices move diagonally; otherwise move toward whichever neighbor cell holds the larger value.

BUILD-LCS(X, Y, dp):
    i = length(X); j = length(Y)
    result = ""

    while i > 0 and j > 0:
        if X[i] == Y[j]:
            result = X[i] + result      // prepend matched character
            i = i - 1; j = j - 1
        else if dp[i-1][j] ≥ dp[i][j-1]:
            i = i - 1
        else:
            j = j - 1

    return result

Worked DP TableCore

For X = "ABCBDAB", Y = "BDCABA":

Space OptimizationAdvanced

If only the length is needed (not the actual subsequence), the table can be compressed to two 1D arrays — a "previous row" and a "current row" — reducing space from O(m×n) to O(min(m,n)), since each row only ever depends on the row directly above it. 

LCS-LENGTH-OPTIMIZED(X, Y):
    m = length(X); n = length(Y)
    prev[0..n] = 0
    cur[0..n]  = 0

    for i = 1 to m:
        for j = 1 to n:
            if X[i] == Y[j]:
                cur[j] = prev[j-1] + 1
            else:
                cur[j] = max(prev[j], cur[j-1])
        prev = cur                // shift current row into previous for next iteration

    return prev[n]
Trade-off

This optimization loses the full history needed to reconstruct the actual LCS string — reconstruction under O(n) space requires more advanced techniques (e.g. Hirschberg's algorithm, which recursively splits the problem to reconstruct the LCS in O(m+n) space).

Time: O(m × n) Space (full table): O(m × n) Space (length only): O(min(m, n))

Related Problems & ExtensionsAdvanced

Longest Common Substring

Like LCS but the match must be contiguous. The recurrence resets to 0 on a mismatch instead of taking a max, and the answer is the maximum value anywhere in the table (not necessarily the bottom-right cell).

if X[i] == Y[j]:
    dp[i][j] = dp[i-1][j-1] + 1
    answer = max(answer, dp[i][j])
else:
    dp[i][j] = 0

Edit Distance (Levenshtein Distance)

Generalizes LCS by allowing insert, delete, and replace operations (each with a cost) to transform X into Y with minimum total operations.

dp[i][j] = dp[i-1][j-1] if X[i] == Y[j]
dp[i][j] = 1 + min( dp[i-1][j], dp[i][j-1], dp[i-1][j-1] ) otherwise  (delete, insert, replace)

Shortest Common Supersequence (SCS)

The shortest string that contains both X and Y as subsequences.

SCS length = m + n − LCS(X, Y) — every character not shared must appear once, and shared characters (the LCS) are reused rather than duplicated.

LCS of Three Strings

Extend to a 3D DP table dp[i][j][k] over prefixes of X, Y, Z:

if X[i]==Y[j] and Y[j]==Z[k]:
    dp[i][j][k] = dp[i-1][j-1][k-1] + 1
else:
    dp[i][j][k] = max(dp[i-1][j][k], dp[i][j-1][k], dp[i][j][k-1])
3-string LCS Time: O(m·n·p)

Printing All LCSs

When the DP table has multiple equally-long paths (ties in the max), more than one distinct LCS of maximum length can exist. Enumerating all of them requires backtracking through every tie branch, which can be exponential in the worst case — typically done with memoized recursive set-building rather than a simple loop.
